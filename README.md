# Tablebones — Theatrical Tabletop Parlor

A web application for playing board games online with friends and players worldwide, styled with a distinct 1930s Fleischer Studios & *Cuphead* aesthetic (hand-inked strokes, cel shading, celluloid grain, warm parchment, and procedural gramophone audio).

## Architecture

TableSkull has an authoritative Node.js game server, React client, PostgreSQL database, and room-scoped WebSocket transport. Only Bonegle and Midnight Alley are available.

- PostgreSQL persists guest profiles, Google account links, rooms, participants, chat, match snapshots, and results.
- The Node server owns all active game rules, scores, timers, bots, and winners. React only renders the state it receives and submits player actions.
- WebSockets authenticate with the guest session token and only receive events for rooms they joined.
- A guest has one active room at a time. A room closes when its last human player leaves, even when bots remain; match history remains persisted.

Source code is separated into `src/frontend` (React), `src/server` (Node HTTP API, WebSocket transport, services, database, and game engines), and `src/shared/types` (common data contracts). The backend starts from [src/server/index.js](src/server/index.js); game rules live under `src/server/games`, independently of WebSocket transport.

See [the architecture guide](docs/ARQUITECTURA_AUTORITATIVA.md) for the connection lifecycle and module responsibilities, and [the game contract](docs/GAME_ARCHITECTURE_CONTRACT.md) for integration details.

For a new game, follow [the integration guide](docs/ANADIR_JUEGO.md), including backend dispatch, database constraints, frontend registration, and tests. Profile avatar images live only in `src/frontend/assets/avatars`; do not duplicate them in `public`.

## Features

### 1. Room Management (Public & Private)
- **Public Parlors:** Browsable via the Public Room Finder with filters by game, search query, open joinable slots, and waiting rooms only. Matches already in progress remain visible but are locked against joining.
- **Private Parlors:** Secret rooms hidden from the public lobby board. Joined exclusively via autogenerated ticket codes (e.g., `TB-8491`, `BONE-924`).
- **Create Room Flow:** Configurable game type, player capacities (min/max), and round clocks.

### 2. Match Abandonment & Quorum Victory Rules
- **Abandon Bout:** Players can forfeit and leave matches at any time with confirmation.
- **Dynamic Host Migration:** If the host abandons, the host mantle is immediately passed to the next active player with a parlor announcement.
- **Walkover Victory:** If an active match drops below its `minPlayers` threshold and one player remains, the server finishes it as a walkover, awards the remaining player, and unlocks the "Walkover Victor" achievement.
- **Authoritative Rematches:** The current host can start a fresh match from a finished room when enough players remain; scores and readiness are reset without reusing the final match snapshot.

### 3. In-Game Chat & Player Muting (Anti-Harassment)
- Real-time parlor chat available in both Pre-game Lobbies and Match Arenas.
- **Player Mute System:** Any player can mute another player with one click (from either the player bar or chat message).
- Muted players' messages are masked to prevent toxicity or harassment, accompanied by visual status indicators.
- Muting unlocks the *"Saloon Peacekeeper"* achievement.

### 4. Pre-Game Lobby ("Vestuario de Combate")
- Player roster displaying avatar, alias, host crown badge, and ready status.
- **Host Kick Ability:** Host can kick disruptive contenders prior to match start with audible bulb-horn feedback.
- Host can pass host role or add bot contenders to test game flows.
- Host can only start once the room meets minimum quorum and contenders are ready.

### 5. Identity, Google Auth & Achievements
- **Guest by Default:** No password is required. A server-issued guest session persists the profile and progress in PostgreSQL.
- **Google Account Linking:** Guests can link a real Google identity through Google Identity Services when the OAuth client ID is configured. The application never stores Google passwords.
- **Avatar Selection:** 8 distinct vector illustrated 1930s character portraits (The Prizefighter, The Ringmaster, The Dice Shark, The Clockmaker, The Iron Baron, The Sea Captain, The Illusionist, The Lucky Gambler).
- **Strictly No Emojis:** All UI icons are clean SVG / Lucide icons.
- **Achievements System:** Unlock achievements with points across games (*First Step in the Ring*, *Prizefight Victor*, *The Gracious Host*, *Underground Society*, *Saloon Peacekeeper*, *Silver Tongue*, *Walkover Victor*, *High Roller Strike*).

### 6. 1930s Procedural Soundstage
- Powered by the browser's Web Audio API and routed through a 78 RPM phonograph bandpass filter (`1400Hz`, `Q 0.65`).
- Procedural brass boxing ring bells, stride-piano block clicks, upbeat victory fanfare, bulb-horn honks, slide whistles, and typewriter bells. Muteable via the top bar toggle.

## Getting Started

### Development
```bash
npm install
docker compose up -d postgres
npm run server
```

In another terminal:

```bash
npm run dev
```

The backend runs at `http://localhost:3000`; Vite runs at `http://localhost:5173/tablebones/` and proxies API/WebSocket traffic to it.

Copy `.env.example` to `.env` before enabling Google account linking. Both `GOOGLE_CLIENT_ID` and `VITE_GOOGLE_CLIENT_ID` must be set to the same Web OAuth client ID.

### Production Build & Local Preview
```bash
npm run build
npm run server
```

### Automated Checks

```bash
npm run build
npm run test:server
```

The tests cover both game engines, HTTP routes/static assets, and real WebSocket connections with mocked database queries. Build first because the static-serving test reads `dist`.

The PostgreSQL lifecycle test is opt-in: set `TABLEBONES_TEST_DATABASE_URL` to a test database connection before running `npm run test:server`. It creates and drops an isolated schema, so the database role must have schema creation permissions. Without this variable, the database test is skipped. `BASELINE_ENGINE_FILE` optionally enables comparison against an earlier engine snapshot during refactoring.

## 🚀 Despliegue en Producción y Gestión con PM2

La aplicación corre en producción gestionada por **PM2** mediante [src/server/index.js](src/server/index.js) y el archivo de configuración [ecosystem.config.cjs](ecosystem.config.cjs).

### ⚡ Chuleta de Comandos PM2 más Importantes

| Acción | Comando | Descripción |
| :--- | :--- | :--- |
| **Ver estado** | `pm2 status` | Muestra el estado (`online`/`stopped`), CPU y memoria de todas las apps. |
| **Ver logs en vivo** | `pm2 logs tablebones` | Muestra la salida estándar y errores en tiempo real. |
| **Últimos logs** | `pm2 logs tablebones --lines 50` | Muestra las últimas 50 líneas de registro. |
| **Reiniciar app** | `pm2 restart tablebones` | Reinicia el proceso tras hacer cambios o compilar. |
| **Recarga limpia** | `pm2 reload tablebones` | Recarga el proceso minimizando tiempo de inactividad. |
| **Detener app** | `pm2 stop tablebones` | Detiene temporalmente la aplicación. |
| **Iniciar app** | `pm2 start ecosystem.config.cjs` | Lanza la aplicación usando la configuración definida. |
| **Guardar estado** | `pm2 save` | Guarda la lista actual para que arranque sola si se reinicia el VPS. |
| **Monitor interactivo**| `pm2 monit` | Panel interactivo en terminal para monitorizar CPU y RAM. |
| **Limpiar logs** | `pm2 flush` | Vacía los archivos de logs si ocupan mucho espacio. |
